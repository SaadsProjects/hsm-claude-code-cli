| R-01 | Major | aidlc/spaces/default/intents/261004-dashboard-deploy-pipelin/construction/infrastructure-design/cicd-pipeline.md > Dependabot table; Assumptions & Open Questions (first bullet) | The `uv` Dependabot ecosystem reads `pyproject.toml` and `uv.lock`. It is not known to update `requirements.in` inputs compiled with `uv pip compile` into hashed `.txt` files. If that is right, no Python dependency PRs will ever appear, and the pin-freshness control (DQ4, NFR1.12 intent) silently does not exist for Python packages. The stated fallback ("regenerate locally on that Dependabot PR") does not help, because there would be no PR to regenerate on. The design records the support as an assumption but gives no verification step and no alternative. | Either pick a supported mechanism (for example the `pip` ecosystem with a pip-compile-style header, or a scheduled workflow that runs `uv pip compile --upgrade` and opens a PR), or add a setup-checklist step that verifies Dependabot opens a Python PR. Rewrite the fallback to say what happens if it does not. | New |
| R-02 | Minor | cicd-pipeline.md > Workflow 3 `deploy` job steps | The `deploy` job lists only the ref guard, loading the key, `git push <target>:refs/heads/production`, and the tag.
