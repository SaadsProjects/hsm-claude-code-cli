### Blocking findings

**T1. The post-deploy check cannot see the build identifier (AC7.1.1, AC9.1.2 vs AC5.1.2, F1).** AC5.1.2 puts the build identifier only in the sidebar of an *allowed* visitor. The wireframes say the sign-in screen has "No sidebar content". The check must never sign in (F1, AC7.3.1). So "confirms the build matches" in AC7.1.1 and the evidence in AC9.1.2 can never pass. Some non-sensitive build marker has to be readable by a visitor who is not signed in, for example a small caption on the sign-in screen or a `dashboard/markers.py` element. Alternatively the check drops the build assertion, which would change FR7.1. Both options are legitimate, and showing the build ID publicly is a small information disclosure, so this is a judgment call for the human. It needs a structured question, and a new AC under US5.1 or US4.1 once answered.

**T2. No story proves that a signed-in visitor who is not allowlisted is turned away in a browser.** Intent success says "a browser test proves that a visitor who isn't allowlisted is turned away". As written, the only browser assertions are about a visitor who is not signed in (AC7.1.1, AC7.2.2). AC4.3.x and AC4.4.x are pure-function and `AppTest` level. US8.2 mentions a fake identity provider but has no AC that signs a fake identity in. Add a browser-marked AC, for example under US8.2: "Given the app on loopback with the fake identity provider, when a fake identity with a verified email not on the allowlist signs in, then the refusal screen (AC4.3.3) shows and no tab renders". Ideally add a second case with an unverified email. F1 is not touched, because the identity is fake and not allowlisted. Effort note: `st.login` needs OIDC settings, so "fake identity provider" means a local OIDC discovery and token stub. Size this in Units Generation. It is not trivial.

### Ambiguous or not directly observable criteria (sharpen)

- **AC1.2.2** Add the boundary: a 32-byte secret is accepted. State that length is measured in UTF-8 bytes. Without that, 16 two-byte characters count differently from 16 ASCII characters.
- **AC1.2.1** Covers minting only. FR1.1 also requires that *verifying* with the variable unset raises. Add "or verified".
- **AC1.3.2** "Outside the documented gitleaks allowlist" understates the exclusions. `PERMANENT_EXCLUSIONS` also excludes `aidlc/spaces/*/intents/**`. Name both, and say the search covers the working tree at HEAD, not history. History is gitleaks' job, under its allowlist.
- **AC1.3.3, AC2.3.1 ("written first"), AC8.3.4, AC10.1.3** are process criteria, not tests. Mark each as *evidence*: the PR file list or `git show --stat` for M1, and the ruleset diff for M2. Squash-merge removes commit order, so "written first" can only be evidenced on the branch, before the squash.
- **AC1.4.1** "Before any server or subprocess starts" is observable only if the secret is set at conftest import or `pytest_configure`, not in a fixture. Say so. Also add: an `HSM_SIGNING_SECRET` already in the developer's shell is overwritten, so tests never use a real `.env.local` secret.
- **AC1.4.2** "Two test runs differ" needs two nested pytest runs, which are slow and brittle. Restate at unit level: the generator returns distinct values on two calls, and conftest contains no fixed secret literal.
- **AC2.2.2** "Starts as before" binds the fixed port 8770 (`run(port=8770)`, start script). A test that runs it breaks the `team.md` rule "new tests bind port 0". Either let the start script and `run()` take a port (env or argument) and assert that a health request answers, or test only the refusal path and a pre-flight function. Add the 31-byte case (FR2.3 says "missing or too short").
- **AC2.3.1** Add a short-secret case. A missing-secret subprocess test must strip the variable from the child's env explicitly, because conftest exports it.
- **AC2.4.1** "Any tool": a parametrized test over the server's tool list is fine. It must be a new test that starts its own MCP subprocess without the secret, not an extension of the sequential `_run()` in `test_mcp_tools.py` on fixed port 8773. **AC2.4.2**: extend it to every committed config FR2.5 names: `.mcp.json`, `.streamlit/config.toml` and `.claude/settings.local.json.example`.
- **AC2.5.2** Say what the visitor sees when the bridge fails closed. "No tab renders" is not enough. The project correction requires a way out on every error screen. Add the precedence when both the environment and Streamlit secrets set the value, and add that a too-short value from Streamlit secrets also fails closed.
- **AC3.1.1** Make it assert that the bound address is exactly `127.0.0.1` (not `0.0.0.0`) and that the port is OS-assigned. **AC3.2.1** "Count running servers" needs an observable: the start function returns the same server object or address on a second call, and only one listening socket exists. Add a **concurrent** case: two threads call start at once. Streamlit runs each session in its own thread, so two first visitors race. Without a lock and a test, AC3.2.1 passes while production starts two backends.
- **AC3.2.2** The singleton lives across `AppTest` runs in the test process. The stories need a test-only stop or reset seam (next to `writes.reset_for_tests`). Without it, backend state leaks between tests, which breaks test independence.
- **AC4.1.2** "No backend call exists": make it a spy on the in-process start function and on `HsmClient`, asserted as not called.
- **AC4.2.2** "Google is the configured provider" has no clear target, because secrets are not committed and `AppTest` cannot follow the `st.login` redirect. Make the provider name a constant passed to `st.login`, and assert the call through the identity adapter (see the next point).
- **AC4.6.2 / AC4.1.1** `st.user`, `st.login` and `st.logout` need a thin adapter that `AppTest` can replace with a fake identity. Otherwise Sign out and Sign in are only reachable in a browser, and that code is uncovered (see Floors). Name the seam in US4.5 or US4.6.

- **AC4.4.1** Define "malformed". At minimum: a TOML string instead of a list (it iterates characters, a real fail-open trap), non-string entries, entries without `@`, and a wildcard entry (`*`, `*@example.com`), which must never match. Also cover missing sign-in settings in `AppTest` (secrets without the auth section).

- **AC7.1.1** "The app answers": Streamlit serves its HTML shell with HTTP 200 even when the script crashes. Define "answers" as the sign-in marker from `dashboard/markers.py` appearing within the timeout.
- **AC7.2.3** State the default timeout and that it is configurable. Test it against a port that was bound and then closed, with a short timeout. Add a fourth case: the build marker is missing (an older build).

- **AC7.4.2** A `workflow_dispatch` workflow can run only after it is on the default branch. This is post-merge evidence and belongs with US9.1. Say that the dispatch workflow is never a required check, because it never reports on a PR.

### Floors and browser-test rules

- **Coverage (95.00 against about 96% measured, about 1 point of headroom).** Browser tests run in a separate job and do not feed `coverage-gate`. So every line in the measured packages (`dashboard/auth_gate.py`, the secrets bridge, `dashboard/markers.py`, `agents/build_info.py`, the `mock_hsm` in-process start) must be hit by plain-suite unit or `AppTest` tests. Streamlit glue that only a browser reaches (the login redirect, logout) would lower coverage. That is why the identity-adapter seam above matters. `# pragma: no cover` is forbidden.
- **Test floor (745).** Browser tests do not count. The first PR (US1.x) rewrites tests that depend on the hard-coded secret. Make sure it replaces them rather than deleting them. The margin is wide (about 811 passing) but should be re-measured at the start of Code Generation (open question in requirements).
- **`scripts/` is unmeasured.** `postdeploy_check.py` and the dev-secret script are held to "happy path plus at least two error cases". For the dev-secret script (US2.1) those cases are present: an existing file and the ignore check. For the check (US7.2), they are browser-only. Factor out the pure logic (argument parsing, build comparison, timeout handling) so plain tests also cover it.
- **Browser rules.** Every new browser test file must match `tests/test_*browser*.py`, carry only the `browser` mark (never `perf` as well), bind port 0 for the app and the fake identity provider, and keep its imports on the watch list. `AppTest` needs a raised default timeout when the in-process backend starts.
